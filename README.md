\# University LMS Analysis



A software analysis of a University Learning Management System (LMS), covering requirements, risks, quality attributes, and the responsible use of AI.



\## About the Project



A University LMS brings students, teachers, and administrators onto one platform for courses, assignments, quizzes, and grades. This project studies how such a system should be designed and what can go wrong, from a Software Engineering point of view.



\## What's Covered



\- Purpose of the system

\- Users and stakeholders

\- 5 Functional requirements

\- 5 Non-functional requirements

\- 3 Risks

\- 3 Quality attributes

\- Where AI can be used in an LMS

\- What can go wrong if AI is used incorrectly



\## Documentation



The full analysis is available in the docs folder: \[University\_LMS\_Analysis.docx](docs/University\_LMS\_Analysis.docx)



\## Conclusion



A good LMS needs both strong features and solid qualities like security, performance, and availability. AI can add value through personalized learning and chatbot support, but it should support teachers, not replace them.
